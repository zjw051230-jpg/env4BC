# env4BC 更新与修复规则

业务包环境钩子的可信顺序固定为：已安装 env4BC、本机带匹配 SHA-256 的 env4BC ZIP、官方 `zjw051230-jpg/env4BC` GitHub Release。显式指定的包校验失败时必须立即停止，不得换用其他来源。Python/ffmpeg 仅允许 winget 官方源；没有可信来源时停止并联系维护人员。

## 核心原则

每次更新执行“缺什么改什么”，不做全盘覆盖，不做目录整理。

1. 先读取 `manifest.json` 和本机安装状态。
2. 只检查 manifest 声明的环境组件。
3. 缺失组件可以补装。
4. 同版本且哈希一致的组件必须跳过。
5. 已有不同版本默认保留；用户明确批准后，先建立带时间戳的同目录备份，再替换单个程序文件。
6. API Key、provider 数据和 CC Switch 数据库只在本机保留，不能进入安装包、Git、日志或聊天。
7. CC Switch 路由只能精确修改 `gpt-5.5 -> deepseek-v4-pro`，其他模型、provider、API Key 和 base URL 不得改变。

## 素材保护红线

更新程序不得读取内容、递归枚举、移动、复制、改名、覆盖或删除：

- 配音和视频工作区；
- 项目目录及隐藏 `.codex`；
- 角色音色、参考图、参考视频和参考音频；
- 剧本、任务 JSON、提示词包；
- 已生成视频、MP3、提交资料；
- 快照、日志、复盘和历史版本。

只允许用户在 API 配置窗口中明确选择一个目标配置目录。即使选择了业务项目，也只能写入该项目既定 API 配置文件，不能触碰同项目其他文件。

## 更新公告必须包含

每一版更新公告必须逐项写明：

- 本版新增或修复的环境组件；
- 精确会修改的文件；
- 明确不会修改的文件和目录；
- 是否需要用户批准替换已有程序；
- 备份位置；
- 素材保护声明；
- 回滚方式；
- 校验结果。

禁止使用“自动整理”“迁移全部数据”“清理旧文件”等模糊表述。
