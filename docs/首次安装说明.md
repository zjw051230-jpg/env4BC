# 安装时请把整个文档发给 Codex

用户不需要打开 GitHub、不需要下载安装包，也不需要使用终端。把这份完整文档作为文件发送给 Codex，然后说：

```text
请按照文档全自动安装。
```

Codex 会负责下载、校验、安装和记录更新入口。API Key 等涉密内容仍由用户在本机程序窗口中填写，不能发送到聊天。

## 用户只需要做三件事

1. 把整份《首次安装说明》文件发送给 Codex。
2. 回答 Codex 询问的本机工作区位置和项目名称。
3. 安装完成后，在 Codex 打开的本机 API 配置程序中填写密钥。

以后更新不需要再次发送文档或 GitHub 链接，只需说：

```text
更新配音工具。
```

或：

```text
更新视频工具。
```

---

## 以下内容由 Codex 完整执行

收到本文件后，Codex 必须把它视为首次安装授权和操作合同。不要要求用户自己访问 GitHub、下载 ZIP、计算哈希、解压文件或执行终端命令。

### 1. 安装前询问

只询问完成安装必需的信息：

1. 配音工作区放在哪里；如果用户不安装配音工具则跳过。
2. 视频工作区放在哪里；如果用户不安装视频工具则跳过。
3. 是否同时安装配音和视频工具。用户未说明时默认两者都安装。
4. 每个已选工具的首个项目名称。

工作区必须是本机路径。不得默认使用服务器、UNC 共享目录、网盘同步目录或现有素材目录。

### 2. 唯一官方来源

Codex 自行访问以下官方仓库的最新正式 Release API，不要求用户操作 GitHub：

- env4BC：`https://github.com/zjw051230-jpg/env4BC`
- 配音工具：`https://github.com/zjw051230-jpg/voice-production-toolkit4bingchuan`
- 视频工具：`https://github.com/zjw051230-jpg/word2video4BC`

当前基准正式版本：

- env4BC：`v1.1.0`
- 配音工具：`v3.0.0`
- 视频工具：`v2.0.0`

优先读取最新正式 Release。禁止使用 prerelease、draft、第三方镜像、搜索引擎下载结果、网盘分享或其他仓库。

### 3. 自动下载与安全校验

对每个需要安装的工具，Codex 必须：

1. 从唯一官方 Release 下载 ZIP 和同名 `.sha256`。
2. 校验下载 URL 的仓库所有者和仓库名完全匹配上面的白名单。
3. 计算 ZIP 的 SHA-256，并与 `.sha256` 中的 64 位哈希完全比较。
4. 解压到新建的本机临时目录。
5. 读取 `manifest.json`、`README.md` 和安装脚本。
6. 运行包内验证器，确认不存在 API Key、provider 导出、CC Switch 用户数据库、数据库备份、素材、成品或运行状态。
7. 校验失败时立即停止，删除临时下载，告诉用户联系维护人员；禁止绕过校验或换用第三方来源。

不要在聊天、日志或最终报告中显示 API Key、token、Cookie 或 provider 密钥。

### 4. 固定安装顺序

必须依次执行：

1. 安装或修复 env4BC。
2. 安装配音工具（如果用户选择）。
3. 安装视频工具（如果用户选择）。
4. 创建首个项目并初始化对应的多 Chat 工作流。
5. 检查隐藏更新记录已经生成。

环境资源不足时严格依次处理：

1. 使用已经安装且验证通过的 env4BC。
2. 使用本机明确记录、带正确 SHA-256 的 env4BC 正式包。
3. 从唯一官方 `zjw051230-jpg/env4BC` Release 下载。
4. 仍无法安全补齐时停止并告诉用户联系维护人员。

Python 和 ffmpeg 只能由 env4BC 通过 Windows `winget` 可信源补齐。禁止从第三方下载站获取环境程序。

### 5. 缺什么改什么

安装和后续更新必须严格执行：

- 缺失的声明工具：安装。
- 已存在且哈希一致：跳过。
- 已存在但版本不同：默认保留并报告；需要替换时先生成带时间戳的工具备份。
- 只允许处理安装包清单声明的工具文件。

无论首次安装还是更新，都禁止扫描、整理、移动、改名、覆盖或删除：

- 项目素材和角色音色；
- 任务 JSON、剧本和台词；
- 生成视频和 MP3；
- 交付版本和历史版本；
- 快照、复盘、日志和问题记录；
- 隐藏 `.codex` 任务记录和 Chat 对应表；
- API 私有配置和 API 池；
- CC Switch 用户数据库、provider 和备份；
- 服务器、共享目录和其他人的工作区。

不得对业务工作区执行 `git pull`、镜像同步、目录清理或“自动整理全部数据”。

### 6. API 与 CC Switch

安装完成后，由 Codex 打开 env4BC 的 `Seedance API配置工具`，让用户只在本机窗口中填写 API Key。Codex 不得询问、读取、复述或记录明文密钥。

CC Switch 只允许在其内部本地路由中精确映射：

```text
gpt-5.5 -> deepseek-v4-pro
```

不得改变任何其他模型映射、provider、API Key、base URL 或数据库字段。需要配置路由时先预览、备份数据库、只改选定 Codex provider、检查数据库完整性，再报告非涉密结果。

### 7. 保存后续更新入口

首次安装必须确认以下隐藏记录存在：

- 配音工作区：`.voice-production-toolkit\update-source.json`
- 视频工作区：`.word2video4BC\update-source.json`

记录中必须包含唯一官方仓库、已安装版本、更新脚本和受保护目录。以后用户只说“更新配音工具”或“更新视频工具”时，Codex 直接读取对应记录并运行隐藏更新器，不再要求用户提供 GitHub 链接或本文件。

只有隐藏更新记录损坏或丢失时，Codex 才能使用本文件中的固定官方仓库恢复记录；仍不得要求用户操作 GitHub。

### 8. 安装完成报告

Codex 最终只报告：

- env4BC、配音工具和视频工具的实际安装版本；
- 配音和视频工作区位置；
- 首个项目位置；
- 隐藏更新记录位置；
- 安装、SHA-256 和包验证结果；
- 已跳过、已备份或仍缺失的环境工具；
- 明确确认没有修改素材、成品、API 私有配置、日志、快照和隐藏任务记录；
- 如果仍需用户操作，只提示在本机 API 配置窗口中填写密钥。

不得在报告中输出密钥、provider 私有字段、数据库内容或第三方下载链接。
